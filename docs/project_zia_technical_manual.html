1. System Architecture & Asymmetric Design

Project Zia (Project FAITH) is engineered around an asymmetric client-server architecture that enables ultra-lightweight, legacy client machines (such as the 2007 MacBook Pro with Intel Core 2 Duo and 128MB NVIDIA GeForce 8600M GT) to enjoy the capabilities of an advanced multimodal AI companion with zero hardware throttling, zero fan noise, and zero thermal degradation.

1.1 Asymmetric Workload Distribution

All resource-intensive background routines—including natural language audio transcription (offline Vosk STT), persistent SQLite queries, scheduled cron jobs, Palakkad Islamic prayer calculations, bi-directional Telegram gateway polling, and neural Edge-TTS voice synthesis—are delegated 100% to the dedicated headless Sony Xperia 1 III smartphone.

Component Sony Xperia 1 III (Server Node) Client Node (MacBook Pro / Desktop)
Operating Role Headless 24/7 background automation hub. Pure user interaction & visual client.
CPU Consumption Octa-core Snapdragon 888 (2.84 GHz Kryo 680). Subagent pool strictly capped at max_workers=2 (<20% CPU). <0.5% CPU in CLI mode; <2% CPU in Minimal Web Mode on 2007 Core 2 Duo.
VRAM Utilization Headless (0MB display VRAM consumed). 0MB VRAM (Minimal Mode / CLI); dynamically loads WebGL only on demand.
Acoustic Core Physical MEMS mic ambient listener + front stereo speakers via Termux API. Web Audio API AnalyserNode waveform visualizer.
Storage Footprint Local SQLite ledgers (habits.db, finance.db), logs, model textures. Zero persistent database requirements; connects over LAN sockets.

1.2 Network & Communication Protocol Stack

Communication between the client devices and the central Xperia server operates entirely across the local area network (LAN) using zero third-party cloud brokers:

  • REST API (HTTP/1.1 on port 5000): Exposes atomic JSON endpoints for chat routing, LifeDesk database operations, IoT switch triggers, and system diagnostics.
  • Bi-Directional WebSocket (WS on port 8765): Provides sub-15ms real-time duplex streaming for natural voice audio packets, Live2D expression mood triggers (F1–F11), and runtime avatar toggle commands.
  • Secure JSON-RPC 2.0 (Port 5001): Dedicated remote bridge allowing the Xperia node to trigger native OS automation, screen locking, and notify-send banners on client machines.

2.2 Battery Longevity & Thermal Throttling Prevention

Critical Hardware Protection: Battery Care & Pass-Through Power Lithium-ion batteries swell and degrade rapidly when held at 100% state of charge under continuous load. On the Sony Xperia 1 III, enable Sony Battery Care in Android Settings → Battery → Battery Care and set the limit to 80% or 90%. Enable H.S. Power Control (Heat Suppression) so the device bypasses the battery completely and powers the Snapdragon chip directly from AC power without generating battery heat.

3. LifeDesk SQLite Integration (Habits & Finance)

Project Zia includes a direct, 100% local database bridge ([`engine/lifedesk_bridge.py`](file:///c:/Users/Student/Documents/Project%20Zia/engine/lifedesk_bridge.py)) that seamlessly connects conversational queries to the user's personal LifeDesk productivity and financial ledgers. All data remains strictly on the device with zero third-party cloud data transmission.

3.1 Database Schemas

The system maintains two SQLite database files in data/lifedesk/:

A. Habits Database (habits.db)

CREATE TABLE IF NOT EXISTS habits (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT UNIQUE NOT NULL,
    category TEXT DEFAULT 'general',
    target_per_day REAL DEFAULT 1.0,
    unit TEXT DEFAULT 'times',
    created_at REAL
);

CREATE TABLE IF NOT EXISTS habit_logs (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    habit_id INTEGER,
    habit_name TEXT,
    value REAL DEFAULT 1.0,
    note TEXT,
    date TEXT NOT NULL,         -- ISO format: YYYY-MM-DD
    timestamp REAL,
    FOREIGN KEY(habit_id) REFERENCES habits(id)
);

B. Personal Finance Database (finance.db)

CREATE TABLE IF NOT EXISTS expenses (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    amount REAL NOT NULL,
    category TEXT NOT NULL,     -- food, transport, bills, tech, general
    note TEXT,
    date TEXT NOT NULL,         -- ISO format: YYYY-MM-DD
    timestamp REAL
);

CREATE TABLE IF NOT EXISTS income (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    amount REAL NOT NULL,
    source TEXT NOT NULL,
    note TEXT,
    date TEXT NOT NULL,
    timestamp REAL
);

4. Ambient Hardware, IoT & ADB Intent Bridges

Project Zia acts as a centralized smart home coordinator. By bridging local REST HTTP microcontrollers and wireless Android Debug Bridge (ADB) network sockets, Zia controls room hardware without relying on proprietary cloud IoT apps.

4.1 ESP8266 / NodeMCU Smart Relays (Under ₹1000 Hardware)

Using affordable ESP8266 / ESP-01S relay modules flashed with open-source firmware (Tasmota, WLED, or custom REST sketches), Zia commands physical 230V room lighting and cooling fans over local Wi-Fi:

+---------------------+ HTTP GET /cm?cmnd=Power%20On +--------------------------+ | Sony Xperia 1 III |--------------------------------->| ESP8266 NodeMCU Relay | | (iot_bridge.py) | | IP: 192.168.1.50 | +---------------------+ +------------+-------------+ | [ 230V AC Relay ] | +-------v--------+ | Desk Lamp/Fan | +----------------+

The Python implementation in [`engine/iot_bridge.py`](file:///c:/Users/Student/Documents/Project%20Zia/engine/iot_bridge.py) sends asynchronous, non-blocking HTTP GET requests with a 2.5-second total timeout, guaranteeing that network delays never freeze the companion's dialogue loop.

4.2 Wireless ADB Projector Media Streaming (miruro.tv)

The bedroom Android projector operates on wireless ADB (port 5555). When the user commands Zia to play media (e.g. "Play the latest episode of Black Clover"), Zia executes an explicit Android View intent: 

# Wireless ADB Intent Dispatch via Python subprocess
adb connect 192.168.1.65:5555
adb -s 192.168.1.65:5555 shell am start -a android.intent.action.VIEW -d "https://miruro.tv"

4.3 Wireless ADB Tablet VoIP Calling (Botim Calling)

To enable hands-free voice calls with family members abroad, Zia connects to an Android tablet on the local network (192.168.1.75:5555), wakes the screen, and launches the Botim VoIP application: 

# 1. Wake tablet display from sleep
adb -s 192.168.1.75:5555 shell input keyevent 224

# 2. Launch Botim Calling Activity
adb -s 192.168.1.75:5555 shell am start -n com.botim.app/.MainActivity -a android.intent.action.MAIN

When the user requests the rich graphical model (or clicks the HUD toggle button), [`client_ui/app.js`](file:///c:/Users/Student/Documents/Project%20Zia/client_ui/app.js) dynamically loads the PixiJS and Cubism 4 runtimes and mounts the Kaguya model:

Live2D Mode (On-Demand) "load avatar" / "live2d mode" ~180MB VRAM 28 FPS capped Dynamically fetches Cubism runtime; mounts Kaguya model with 4K Lanczos downscaled textures.

6. Remote Telegram Gateway & Neural TTS Voice Notes

When the user is away from the home Wi-Fi network, [`engine/remote_gateway.py`](file:///c:/Users/Student/Documents/Project%20Zia/engine/remote_gateway.py) maintains a secure, encrypted bridge via the Telegram Bot API.

6.1 Zero-Framework Architecture

Unlike heavy Python bot frameworks (such as python-telegram-bot or aiogram) that consume 60–100MB of RAM, Zia's gateway is implemented using Python standard library urllib.request, consuming less than 5MB of RAM on the Xperia smartphone.

6.2 Bi-Directional Command & Query Processing

The gateway continuously polls Telegram servers via long-polling (timeout=25s) inside a background daemon thread. It parses commands and natural language prompts:

  • /status: Returns Xperia CPU usage, battery percentage, RAM consumption, and subagent state.
  • /prayer: Returns astronomical prayer times for Palakkad, Kerala and countdown to next prayer.
  • /alarms: Lists all pending clock alarms and relative countdown timers.
  • /habits: Queries habits.db and outputs daily habit completion streaks.
  • /expenses: Queries finance.db and outputs today's spending and monthly ledger breakdown.
  • Natural text prompts: Evaluated by Gemini Flash AI brain and returned with emotional tone.

6.3 Neural Edge-TTS Voice Note Synthesis

When an audio response is requested (via /voice <prompt> or system notification alarms), Zia bypasses standard text and generates a natural, playable voice note: 

# 1. Synthesize neural speech via Microsoft Edge-TTS (voice: en-US-AriaNeural)
communicate = edge_tts.Communicate(text, voice="en-US-AriaNeural")
await communicate.save(output_audio_path)

# 2. Upload as native voice note via Telegram sendVoice multipart POST
POST https://api.telegram.org/bot/sendVoice

[chat_id: ]
[voice: binary/audio/mpeg]
